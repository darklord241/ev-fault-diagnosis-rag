## Retrieval — Overview

- `load_chunks()` handles reading data.

- `_validate_chunk()` handles chunk structure.

- `_normalized_vector()` handles vector validity and normalization.

- `CosineIndex.__init__()` prepares the searchable collection.

- `CosineIndex.search()` ranks the collection against a query.

- `SearchResult` packages each hit.

- Embedder describes the future model interface.

Retrieval is the process of finding the most relevant chunks from our existing document corpus for a given user query.

### 1. Creating Chunk Embeddings

The retrieval pipeline loads the existing chunks from the chunked JSONL files and passes each chunk's text to an embedding model. The model converts each chunk into a numerical vector called an **embedding**, which represents its semantic meaning.

These embeddings can be stored alongside their corresponding chunk IDs and original chunk data, including the text, source information, provenance, and metadata. This avoids having to regenerate the chunk embeddings for every query, as long as the corpus and embedding model remain unchanged.

This creates the foundation for semantic search.

### 2. Embedding the User Query

When a user submits a natural-language query, the same embedding model converts the query into a vector in the same embedding space as the chunk vectors.

For example:

> What should I check if charging does not start?

The resulting query vector can now be compared with the vectors representing our document chunks.

### 3. Ranking Chunks Using Cosine Similarity

The system calculates the cosine similarity between the query vector and each of the 407 existing chunk vectors. Cosine similarity measures how closely the vectors align, allowing the system to rank chunks according to their semantic similarity to the query.

The system then selects the **top 5 highest-ranked chunks** and returns their original content and associated source metadata.

### Overall Workflow

1. Load the existing chunks.
2. Generate and store an embedding for each chunk.
3. Convert the user's query into an embedding using the same model.
4. Calculate cosine similarity between the query vector and all chunk vectors.
5. Rank the chunks and retrieve the top 5 results.
6. Pass the retrieved evidence to the answer-generation component in a later stage.

**Current implementation status:** 
Stage 1 provides the chunk loader, vector validation, and cosine-similarity ranking logic. It does not yet generate embeddings. Connecting a real embedding model and generating the chunk and query vectors will be implemented in Stage 2.
