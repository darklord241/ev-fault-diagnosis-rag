# MiniLMEmbedder — EV Fault Diagnosis RAG

## 1. Purpose

`MiniLMEmbedder` implements the embedding backend interface using `sentence-transformers/all-MiniLM-L6-v2`.

It acts as an adapter between the model-independent retrieval pipeline and the Sentence Transformers library.

The backend handles:
- Model initialization
- Token counting and length validation
- Single-text and batch embedding
- Conversion of model output into Python numeric vectors
- Recording model and preprocessing identity

## 2. Model initialization

Important attributes:

- `MODEL_ID`: identifies the pretrained model.
- `DEFAULT_REVISION`: defaults to `main`, which is mutable and not reproducible by itself.
- `device`: selects the inference device, such as CPU.
- `batch_size`: controls the number of texts processed per encoding batch.
- `local_files_only`: controls whether the model may be downloaded.
- `model`: optional dependency injection for tests or externally created models.

The model is loaded during initialization only when a model was not injected.

## 3. Model capabilities

The constructor reads:
- `max_seq_length`: maximum supported sequence length.
- `tokenizer`: converts text into token IDs.
- Embedding dimension: number of values in each output vector.

For the tested MiniLM model:
- Maximum sequence length: 256 tokens.
- Embedding dimension: 384.

## 4. Embedding identity

`EmbeddingIdentity` records:
- Model ID
- Revision
- Preprocessing description
- Embedding dimension

This information helps the embedding cache distinguish different model configurations.

**Important:** `main` is not an immutable revision. Pin a verified model commit before depending on reproducible embedding caches.

## 5. Token validation

`token_count(text)` tokenizes the input with special tokens enabled and truncation disabled.

`_validate_input_length(text, context)`:
1. Validates that the text is a non-empty string.
2. Counts tokens.
3. Raises `InputTooLongError` when the count exceeds `max_seq_length`.
4. Returns the original text if it passes.

The backend rejects oversized inputs rather than silently truncating or rewriting them.

## 6. Encoding

`_encode(texts)` calls `SentenceTransformer.encode()` with:
- Configurable batch size
- Progress display disabled
- NumPy output requested
- Model-side embedding normalization disabled

The result is converted into Python tuples of floats. The method also checks that the number of returned vectors matches the number of input texts.

The shared `validate_vector()` function elsewhere in the embedding module validates dimensions, rejects non-finite or zero vectors, and performs L2 normalization.

## 7. Public methods

### `embed(text)`
Validates one text and returns its embedding vector.

### `embed_query(text)`
Uses the same embedding path as `embed()` because this model configuration does not apply separate query preprocessing.

### `embed_documents(texts)`
Rejects a string passed instead of a sequence, validates every document, and embeds the documents as a batch.

## 8. Key Python concepts

- **Dependency injection:** supplying a model through the constructor rather than constructing it internally.
- **`getattr()`:** retrieves an attribute with an optional fallback value.
- **`callable()`:** checks whether an object can be called.
- **`enumerate()`:** iterates over values while providing their indices.
- **List comprehensions:** build a list by transforming each item.
- **`try`/`except`:** converts lower-level errors into clearer backend-specific errors.
- **`Sequence[str]`:** type annotation describing a sequence of strings.
- **Batch processing:** processes multiple texts through a shared model call.
- **Tokenization:** converts text into tokens/token IDs before neural-network processing.
- **L2 normalization:** scales a non-zero vector to unit length.

## 9. Project-specific concern

Eleven of the 407 corpus chunks exceed the 256-token limit. Since `embed_documents()` validates the entire batch before encoding, an oversized chunk can cause the batch to fail.

Before building the production embedding cache, choose an explicit policy for those chunks. Do not silently truncate them or modify the corpus without deciding how to preserve retrieval quality and provenance.

## 10. Mental model

`MiniLMEmbedder` does not implement the neural network itself. It prepares and validates text, delegates vector generation to Sentence Transformers, converts the output to a consistent representation, and exposes it through the retrieval project's existing embedding interface.


# MiniLM Real-Model Smoke Test

## Purpose

The smoke test checks whether `MiniLMEmbedder` works with the actual cached MiniLM model. It is opt-in because loading and running a real model is slower than running unit tests with fake models.

## Enabling the test

The environment variable `RUN_MINILM_SMOKE` must equal `"1"`.

The `unittest.skipUnless()` decorator skips the test class when the variable is not enabled.

## Test sequence

1. **Load the model:** Instantiate `MiniLMEmbedder(local_files_only=True)` so model files must already exist locally.
2. **Check configuration:** Verify the embedding dimension is 384 and maximum sequence length is 256.
3. **Check query embedding:** Embed one hardcoded query and verify that its vector has 384 values.
4. **Check batch embedding:** Embed two hardcoded sample documents and verify that two 384-dimensional vectors are returned.
5. **Inspect the corpus:** Call `load_chunks()` to load the actual project chunks.
6. **Find oversized chunks:** Count tokens in every chunk and collect those exceeding 256 tokens.
7. **Report chunk IDs:** Print up to five IDs to help locate oversized records.
8. **Check error handling:** Verify that embedding the first oversized chunk raises `InputTooLongError`.

## Important distinction

The two sample documents used for the embedding checks are hardcoded test data, not actual corpus chunks.

The real corpus is used only for the token-limit scan and the oversized-input error check. The smoke test does not embed all corpus records or evaluate retrieval rankings.

## What the test verifies

- The real model loads from the local cache.
- Query and batch embedding return the expected vector dimensions and counts.
- The corpus can be scanned for inputs exceeding the model limit.
- The backend rejects an oversized input with the expected exception.

## What the test does not verify

- Semantic relevance scores
- Retrieval ranking quality
- Whether the best chunk is returned for a real EV question
- Whether the full corpus can be embedded without handling oversized chunks

## Result from the current run

The smoke test passed, and 11 of the 407 corpus chunks exceeded the 256-token limit. This is a finding to address before building the complete production embedding cache, not evidence that the retrieval system itself is failing.

## Key concept

A smoke test verifies that the basic integration works. Retrieval evaluation is a separate step that measures whether the system returns useful, relevant chunks for actual queries.
